## Genuine external blockers and exact next steps

- Shopify remote installation, dynamic commerce/editor/app compatibility: provide an authorized development store and authenticate Shopify CLI; push an unpublished theme, upload/bind exact assets, execute independent native QA and retain evidence. The V1 adapter intentionally does not accept a text selection as remote PASS.
- Live publication/domain/TLS/hosting: configure a target deployment integration/environment, validate the candidate there, preserve rollback, then obtain explicit release authorization. No live site or DNS was changed.
- Optional Claude: configure ANTHROPIC_API_KEY for an actual consultation. Core operation does not depend on it.
- Arbitrary web-app/Webflow/business integrations: add a compatible adapter; current bounded requirements produce honest decisions rather than fabricated implementation.

All reversible local implementation/testing/package work proceeds without those optional credentials. Unsupported project-specific requirements remain blocked even if the generic Engine itself is working.
